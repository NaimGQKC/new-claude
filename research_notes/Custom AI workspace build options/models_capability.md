## 1. What do independent benchmarks say? Do cheap/open models match frontier?

### Takeaway
No, not across the board. On the most up-to-date independent composite (AA Intelligence Index v5, Oct-Nov 2026) the best open-weights model (Kimi K3.1 Pro, 46) trails the best closed model (Claude Fable 5.2, 65) by ~19 points, and the cheapest open models people usually call "near frontier" (DeepSeek V4.1 Flash 33, GLM-5.3 32) sit below even Anthropic's cheapest frontier-lab model (Claude Haiku 5.5, 36). The gap looks much smaller on human-preference voting (Arena: open Kimi K3 1487 vs top 1526) and on vendor-reported agent/coding tables, and it is mid-sized on Vals AI's enterprise-task index (Kimi K3.1 Pro 62.5% and DeepSeek V4.1 Flash 61.3% vs top 71.3%). The user's claim is "partly true, depending on the benchmark and on task type": cheap models are close on Arena-style preference and some coding/terminal tasks, but clearly behind on private-set knowledge-work, science, hallucination/knowledge-reliability and long-horizon agent work.

### Inferences
- Gap on the independent, private-set, hard-task composite is large (AA v5: ~19 pts best-open vs best-closed; ~32 pts for the cheap open weights people actually deploy cheaply), but on Vals' enterprise-tasks index DeepSeek V4.1 Flash is only ~10 pts behind the best closed model while costing ~1/27 as much per test. For a routing product the cost-adjusted picture favours open models for routine/mid-difficulty work.
- Each lab's own cheap tier is a direct competitor to open models: Claude Haiku 5.5 (AA 36, Vals 58.7, $0.10/$0.50 per 1M per Fastero) and Muse Ember (AA 36, Vals 60.5, $0.14 task cost) match or beat DeepSeek V4.1 Flash (33) and GLM-5.3 (32) on AA. A router should treat Haiku/Luna/Flash-class closed models as candidates, not only open weights. (Haiku price from a third-party tracker; AA task cost Haiku $0.41 vs DeepSeek V4.1 Flash $0.60.)
- Vendor tables use older benchmark versions and older frontier comparators; the same model drops sharply on AA v5 / Vals Terminal-Bench 4.0. Do not use vendor numbers for routing thresholds.

## 2. Tool calling / agentic reliability, structured output, long-horizon browsing

### Takeaway
Agentic benchmark scores for open models are strong on vendor tables but weaker on independent harder suites (Terminal-Bench 4.0: DeepSeek V4.1 Flash 31.8% on Vals vs 63-65% for Claude). In practice the largest documented problems are integration-level: DeepSeek V4.1's custom DSML tool-call markup leaking into text / malformed / unreliable parallel calls, reasoning_content round-tripping requirements, always-on thinking (GLM-5.3), and very slow, tool-call-heavy runs (Kimi K3.1 Pro).

### Cited Findings
- DeepSeek V4.1 Flash tool-call failure modes reported on GitHub: DSML tags written as plain text open a tool call and trigger HTTP 500 (NVIDIA spark-local-inference #144); missing `tool_calls` with DSML markers leaking into `content` (CommandCode #909); repeated malformed DSML calls ending turns with stop and no tool execution (oh-my-pi #15178); vLLM parser issues with spaced DSML tags / drifted openers / empty args on truncation (vLLM PR #61142, issue #62051); unreliable parallel tool calls with a documented workaround of batching into one "parallel executor" tool (deepseek-ai/awesome-deepseek-agent #483). Many reports are about self-hosted vLLM parsers, not the hosted API. — [NVIDIA #144](https://github.com/NVIDIA/spark-local-inference/issues/144); [command-code #909](https://github.com/CommandCodeAI/command-code/issues/909); [oh-my-pi #15178](https://github.com/can1357/oh-my-pi/issues/15178); [vLLM #62051](https://github.com/vllm-project/vllm/issues/62051); [awesome-deepseek-agent #483](https://github.com/deepseek-ai/awesome-deepseek-agent/issues/483)
- DeepSeek thinking mode: reasoning_content from an assistant tool-call turn must be passed back on later requests or the API can return HTTP 400 (per a secondary blog). — [aifreeapi](https://www.aifreeapi.com/en/posts/deepseek-v4-tool-calling-local-agent-troubleshooting)
- Kimi K3.1 Pro: for multi-turn tool use the full assistant message including `reasoning_content` and `tool_calls` must be returned to `messages`; recommended sampling temperature 1.0, top-p 0.95. — [HF Kimi-K3.1-Pro](https://huggingface.co/moonshotai/Kimi-K3.1-Pro)
- Kimi K3.1 Pro hands-on: a Hacker News commenter found it slow because it issues many tool calls (73 queries on a data-quality task vs 18 for GPT-6.1 Sol); one reviewer scores intelligence 4.5/5, price/token 4.5, token efficiency 2.5, speed 2 (overall 3.5/5); gaps noted in browser validation and a data-grouping error. — [HN item 50212065](https://news.ycombinator.com/item?id=50212065); [eesel review](https://www.eesel.ai/blog/kimi-k3-1-pro-review); [Evolink review](https://evolink.ai/blog/kimi-k3-1-pro-review)
- Independent agentic data: Vals Terminal-Bench 4.0 — Kimi K3.1 Pro 63.6, Claude Fable 5.2 65.2, Sonnet 5.5 64.1, GPT-6.2 Astra 63.1, **DeepSeek V4.1 Flash 31.8**, MiniMax-M3.1-Flash 25.25. — [Vals Index](https://www.vals.ai/benchmarks/vals_index); [Vals MiniMax](https://www.vals.ai/models/minimax_MiniMax-M3.1-flash). AA: Kimi K3.1 Pro Terminal-Bench 4.0 67% (vs Sonnet 5.5 64%) — [AA article](https://artificialanalysis.ai/articles/kimi-k3-1-pro-launch-benchmarks). So the top open model (Kimi) matches closed on terminal-style agentic coding; the cheap ones (DeepSeek Flash, MiniMax Flash) do not.
- AA AutomationBench-AA (agentic business-app tasks): Kimi K3.1 Pro 73% (K3 58%) — [AA article](https://artificialanalysis.ai/articles/kimi-k3-1-pro-launch-benchmarks). DeepSeek vendor claims AutomationBench 54.8 vs Opus 5.0 50.3 (different harness) — [HF DeepSeek-V4.1-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash)
- Vendor-reported long-horizon/computer use: Kimi K3.1 Pro OSWorld V2.1 79.6 vs Opus 5.5 81.8; DeepSeek V4.1 Flash OSWorld V2.1 69.3; MiniMax M3.1 Flash OSWorld V2 61.7 — [HF Kimi](https://huggingface.co/moonshotai/Kimi-K3.1-Pro); [MiniMax X](https://x.com/MiniMax_AI/status/2113436864904610008)
- Diagnosing search failure modes of long-horizon search agents is an active research area (arXiv Aug 2026), but no per-model result retrieved — [arXiv 2608.01913](https://arxiv.org/pdf/2608.01913)
- Structured output / function calling support: GLM-5.3 supports function calling and JSON structured output (Z.ai docs); Kimi K3.1 Pro lists structured output, tool choice, partial mode, dynamic tool loading, context caching. — [Z.ai docs](https://docs.z.ai/guides/llm/glm-5.3); [HF Kimi](https://huggingface.co/moonshotai/Kimi-K3.1-Pro)
- GLM-5 (earlier gen) HN comments: output quality degrades well before max context (~40k tokens), advice to keep one topic per chat; "step down from SOTA"; skips investigation before acting. About nine months old, may not apply to 5.3. — [HN GLM-5 thread](https://news.ycombinator.com/item?id=46974853)
- Benchmark integrity: Anthropic reported Claude Opus 4.6 hypothesised it was being evaluated in 9 of 1,266 BrowseComp problems; BrowseComp near-saturated for top systems. — [OpenAI BrowseComp](https://openai.com/index/browsecomp/) (via search summary; low specificity)

### Inferences
- For an agentic router, the "tool-call dialect" is an engineering cost: DeepSeek's DSML and the reasoning_content round-trip require a normalising gateway (LiteLLM/OpenRouter-like or custom) and a retry/repair layer. Using hosted APIs (not self-hosted vLLM) removes most parser issues.
- Kimi K3.1 Pro is the only open model with evidence (independent AA + Vals Terminal-Bench ≈ closed) of closed-frontier-class agentic ability, but at ~31 tok/s and many tool calls it is slow and not "cheap per task" ($3.68/Index task vs Sonnet 5.5-class ~$10 per AA leaderboard and GPT-6.2 Sol $1.01).
- Cost per task, not per token, is what matters: GPT-6.2 Sol Max (AA 57) costs $1.01 per Index task per AA vs DeepSeek V4.1 Flash $0.60 (AA 33) and Kimi K3.1 Pro $3.68 (AA 46). Closed "efficient" tiers dominate on AA's intelligence-per-dollar. — [AA leaderboard](https://artificialanalysis.ai/leaderboards/models)

### Gaps
- No independent multi-step browsing / long-horizon web-agent benchmark (e.g., WebArena, BrowseComp-Plus, Mind2Web) numbers for the named 2026 models were retrieved.
- No tau2-bench numbers for any of these models (Kimi card says tau2 not reported; AA v5 dropped tau2).
- No quantified structured-output (JSON schema adherence) comparison across models.
- Real-world Kimi/GLM tool-calling reports were thin; most review sites are SEO.

## 3. Document/report writing quality, multilingual, vision/multimodal per model

### Takeaway
There is little independent evidence on long-form report writing; the best proxies are AA's GDPval-AA (expert knowledge-work deliverables, Elo) and Arena text preference where Kimi K3.1 Pro is near the top for open models. Vision: Kimi K3.1 Pro, DeepSeek V4.1 Flash, MiniMax M3.1 Flash, Qwen4 Max, GLM-5.3-Flash accept images; GLM-5.3 (base) and DeepSeek V4 Pro 0813 are text-only; Qwen3.8 open weights are text-only.

### Cited Findings
- GDPval-AA (AA, Elo): April 2026 (older gen) DeepSeek V4 Pro 1554, GLM-5.1 1535, Kimi K2.6 1484; Oct 2026 Kimi K3.1 Pro 1846 vs Claude Opus 5.5 1866 and Muse Wonder Full 1857 (K3 was 1534). — [AA V4 article](https://artificialanalysis.ai/articles/deepseek-is-back-among-the-leading-open-weights-models-with-v4-pro-and-v4-flash); [AA Kimi article](https://artificialanalysis.ai/articles/kimi-k3-1-pro-launch-benchmarks). Kimi card (vendor-run) GDPval-AA: DeepSeek V4.1 Flash 1746, GLM-5.3 1650, Fable 5.1 1754, GPT-6 Astra 1573 — [HF Kimi](https://huggingface.co/moonshotai/Kimi-K3.1-Pro) (note: GDPval-AA was dropped from AA Index v5; this number is vendor-reported on the Kimi card)
- Vals AI Vibe Code / legal / finance results (see Q1) are the closest independent "professional output" tests: DeepSeek V4.1 Flash Legal Research 45.2 vs Fable 5.2 46.2; Tax Agent 44.4 vs Sonnet 5.5 42.0 — [Vals Index](https://www.vals.ai/benchmarks/vals_index)

### Inferences
- Kimi K3.1 Pro is the only open model with evidence of near-Opus-5.5 deliverable quality (GDPval-AA 1846 vs 1866, independent AA). DeepSeek V4.1 Flash/GLM-5.3 numbers for document work are vendor-run only.
- For a document/report pipeline, a sensible pattern is cheap open model for drafting sections / extraction and a frontier model for final synthesis and fact-check; the data supports a quality gap on hallucination (Section 5) more than on prose fluency.

### Gaps
- No independent long-form report-writing evaluation (length, citation fidelity, structure) for these models except DeepResearch Bench (Section 4).
- No independent multilingual (non-English/Chinese) evaluation for 2026 models.
- No independent vision benchmark for DeepSeek V4.1 Flash or GLM-5.3-Flash.

## 4. Specialised / distilled small models (summarisation, extraction, reranking, research agents, GUI/browser agents)

### Takeaway
Purpose-trained small open models exist for retrieval/reranking and GUI control, and 30B-class research agents (Tongyi DeepResearch) exist, but independent evidence shows they trail the frontier deep-research systems; GUI-agent leaderboards for open models are maintainer-run and shaky.

### Cited Findings
- Tongyi DeepResearch (Alibaba, 30.5B params, open weights/framework): vendor-reported BrowseComp 43.4, BrowseComp-ZH 46.7, HLE 32.9, WebWalkerQA 72.2, GAIA 70.9; Pass@3: BrowseComp 59.64, BrowseComp-ZH 63.67, HLE 45.9. Report dated 2026-05-19 on arXiv listing (v1 was Oct 2025). — [arXiv 2510.24701](https://arxiv.org/pdf/2510.24701). Compare Kimi K3.1 Pro vendor BrowseComp 92.1 ([HF Kimi](https://huggingface.co/moonshotai/Kimi-K3.1-Pro)): the large general open model far outperforms the 30B specialist on the same benchmark (vendor vs vendor).
- DeepResearch Bench (ICLR 2026 paper; RACE report-quality score judged by an LLM): Tongyi DeepResearch overall 40.46; LangChain Open DeepResearch with GPT-5 50.60 (49.33 in an Aug 2026 snapshot); leaderboard moved to GPT-5.5 as judge in May 2026 (scores not comparable across judges); top entries mid-Sept/Oct 2026 are agent systems ~55-57 (ZTE-Nebula 57.27, 1688AILab 56.53, ATH-Voicepica 56.37, LongCat-DeepResearch 56.21 self-reported, CellCog 56.72 vendor claim). No pure-open-model leaderboard confirmed. — [ICLR 2026 paper](https://proceedings.iclr.cc/paper_files/paper/2026/file/465f22be10e07b301c6ed58f0472f704-Paper-Conference.pdf); [LongCat report](https://arxiv.org/pdf/2609.36071); [benchmarklist](https://benchmarklist.com/benchmarks/deepresearch_bench/); [CellCog](https://cellcog.ai/benchmarks) (vendor)
- MiroThinker: "MiroThinker: Pushing the Performance Boundaries of Open-Source Research Agents via Model, Context, and Interactive Scaling" (arXiv, 21 Apr 2026); no benchmark numbers retrieved. — title only, seen in a search result listing; no URL retrieved for the paper itself (see Gaps)
- Other research-agent efforts: Step-DeepResearch tech report; DeepDive; DeepMiner-32B (33.5 BrowseComp-en per a third-party table). — [Step-DeepResearch](https://arxiv.org/pdf/2512.20491); [DeepDive](https://arxiv.org/pdf/2509.10446)
- Reranking / embedding: Qwen3-Reranker 0.6B/4B/8B (Apache 2.0): MTEB-R 65.80 (0.6B), 69.76 (4B), 69.02 (8B); CodeRAG 73.42 (0.6B) vs 81.20 (4B); Qwen3-Embedding-8B was #1 on MTEB multilingual as of June 5 2025 (70.58; stale). Qwen3-VL-Embedding/Reranker (2B, 8B) for multimodal retrieval (Jan 2026). A 2026 practitioner guide defaults to bge-reranker-v2-m3 with Qwen3-Reranker-4B as accuracy ceiling (opinion, not verified benchmark). — [Qwen3 Embedding paper](https://arxiv.org/pdf/2506.05176); [Qwen3-VL-Embedding paper](https://arxiv.org/pdf/2601.04720); [builderai.tools](https://builderai.tools/blog/best-open-source-embedding-models-2026)
- GUI / browser agents: UI-TARS lineage (ByteDance; UI-TARS-1.5-7B OSWorld 27.5; UI-TARS-1.5 42.5 — vendor, 2025-era). Newer open candidates mentioned by a vendor blog: H Company Holo 3.1 (Apache 2.0, claimed 82.56% OSWorld-Verified on a maintainer-run board) and MAI-UI (Qwen3-VL based) — unverified. — [bytedance/UI-TARS](https://github.com/bytedance/ui-tars); [eesel GUI agents](https://www.eesel.ai/blog/qwen-ui-agent-alternatives) (vendor blog)
- General open LLM computer-use (vendor): Kimi K3.1 Pro OSWorld V2.1 79.6; DeepSeek V4.1 Flash 69.3; MiniMax M3.1 Flash 61.7. Closed: Opus 5.5 81.8. — [HF Kimi](https://huggingface.co/moonshotai/Kimi-K3.1-Pro)

- Web page reading / extraction: no 2026 benchmark found for dedicated page-reading small models (e.g., ReaderLM-type); I did not retrieve evidence. See Gaps.

### Inferences
- Where a specialised small model is plausible for a self-hosted workspace: embeddings/reranking (Qwen3 family, bge), vision-language GUI grounding (Qwen3-VL-based, Holo), cheap triage/extraction (Haiku 5.5, GPT-6 Luna, DeepSeek V4.1 Flash). For the deep-research agent itself, general large models (Kimi K3.1 Pro, DeepSeek V4.1 Flash with tool use) have much stronger vendor-reported BrowseComp than 30B specialists.
- The UI-TARS repo archival is a maintenance-risk signal for a browser-agent roadmap; prefer actively maintained VLM backbones (Qwen3-VL family) or a frontier computer-use model.

### Gaps
- MiroThinker's actual benchmark numbers and licence not retrieved.

- OSWorld-Verified leaderboard values for Holo 3.1 etc. unconfirmed.
- DeepResearch Bench: no authoritative open-model-only table; judge change in May 2026 breaks time comparisons.

## 5. Real-world user reports: hallucination, instruction drift, refusal, language mixing

### Takeaway
Independent hallucination/knowledge-reliability evidence shows open Chinese models hallucinate more than the best closed models (AA-Omniscience), though Kimi K3.1 Pro has improved markedly. Refusals come mainly from Chinese-model content filters on politically sensitive topics. Language mixing: no credible documented measurement found.

### Cited Findings
- AA-Omniscience hallucination rate (lower better): Kimi K3.1 Pro 44% (Oct 23, pre-v1.1; K3 53%; accuracy 51%); Gemini 4 Argon (High) and Gemini 4 Carbon (Medium) 4% on the v1.1 leaderboard (the lowest listed on the AA page); Qwen4 Max 28.4% vs GLM-5.3 38.9% (OrcaRouter citing AA v5.0.1). April 2026: DeepSeek V4 Pro 94%, V4 Flash 96%. Net Omniscience: Claude Fable 5.2 Max 67 (accuracy 79%). — [AA Kimi article](https://artificialanalysis.ai/articles/kimi-k3-1-pro-launch-benchmarks); [AA Omniscience](https://artificialanalysis.ai/evaluations/omniscience); [OrcaRouter](https://orcarouter.ai/blog/qwen-4-vs-glm-5-5); [AA V4 article](https://artificialanalysis.ai/articles/deepseek-is-back-among-the-leading-open-weights-models-with-v4-pro-and-v4-flash)

- Language mixing / code-switching: No source documented this for 2026 models. Only the V2EX "invented expressions" anecdote for DeepSeek V4.1 Flash. — [arXiv 2604.19139](https://arxiv.org/pdf/2604.19139)

### Inferences
- A deep-research product has citation/factual-fidelity as the central risk; AA-Omniscience says closed Gemini 4 / Claude have materially lower hallucination than open models (open: roughly 30-45% rates vs 4% for Gemini 4). Use frontier models (or verification passes) for final claims; cheap models are safer for retrieval, extraction and drafting with source-grounded context.
- Be careful with vendor "hallucination" metrics: each vendor's own bench has them winning.

### Gaps

## 6. API compatibility, reasoning toggles/effort, context windows

### Takeaway
All major open/cheap models expose OpenAI-compatible chat-completions endpoints (most also Anthropic-compatible), 1M context is now standard on hosted APIs, and each has a different reasoning knob (`reasoning_effort` low/high/max; `thinking` toggle; DeepSeek integer effort). Gotchas: GLM-5.3 cannot disable thinking; Qwen3.8 open weights are text-only with 262k native context; reasoning_content must be echoed back.

### Cited Findings
- DeepSeek: OpenAI-compatible `https://api.deepseek.com`; Anthropic-compatible `https://api.deepseek.com/anthropic`; models `deepseek-flash` (served by V4.1 Flash 1017) and `deepseek-v4-pro`; legacy `deepseek-v4-flash` names retired but routed to V4.1 Flash; `thinking: {"type":"enabled"}` toggle (extra_body) and `reasoning_effort` (e.g., "high"). — [DeepSeek API docs](https://api-docs.deepseek.com/). Model card: continuously adjustable effort 1-100 (max=100), 1M ctx, MIT. — [HF DeepSeek-V4.1-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash). Pricing (AA): V4.1 Flash $0.30/$1.20 (98% cache discount); V4 Pro 0813 $1.32/$3.96. — [AA](https://artificialanalysis.ai/models/deepseek-v4-1-flash-1017); [AA V4 Pro](https://artificialanalysis.ai/models/deepseek-v4-pro). Hosted on 21 providers (V4.1 Flash).
- Kimi K3.1 Pro: platform.kimi.ai model `kimi-k3.1-pro`; OpenAI- and Anthropic-compatible; top-level `reasoning_effort` low/high/max (default max); 1M ctx; vision input, structured output, tool choice, context caching; $2/$10 per 1M (cache hit $0.20). — [HF Kimi](https://huggingface.co/moonshotai/Kimi-K3.1-Pro); [AA article](https://artificialanalysis.ai/articles/kimi-k3-1-pro-launch-benchmarks)
