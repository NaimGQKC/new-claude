# Security and sharing: what we decided (2026-11-20)

Principle: the product is **cheap + efficient + fits the workflow**. Security is real but small and fast to deliver (hours, not weeks). Anything that needs weeks or big money waits until a customer asks.

## Doing now (built, in `mvp/`)
| Control | How | Status |
|---|---|---|
| Staff log in with the company's Google or Microsoft account | LibreChat Google / OpenID (Entra) login, restricted to the company's email domain, local passwords off. `install.sh` asks for the IDs | Built; tested that the Google button turns on and password login turns off. Not tested against a real Google/Microsoft tenant |
| Data retention and deletion | Conversations auto-delete after N days (installer asks, default 90). Users can delete earlier | Built; LibreChat accepts the setting |
| Encrypted backups | `backup.sh` makes an AES-256 encrypted file; passphrase generated by the installer | Built and tested (decrypts with the passphrase, listing works) |
| Admin spending limit | Admin page `/gasto` (password protected): set a monthly limit in euros, see spend per person. Warns at 80%, stops at 100% | Built and tested (form, password, one-time token). Per-person attribution via the user's email header: header placeholder exists in LibreChat; end-to-end attribution still being verified |
| Plain-language privacy page | `/privacidad`, with a "test version, no real client data" banner while on OpenRouter | Built; needs a lawyer's review before real customers |
| Self-check | `scripts/selfcheck.sh`: permissions, default passwords, open sign-up, headers, exposed ports, pinned images | Built and passing |

## Not doing (on purpose)
- Outside penetration test, SOC 2, ISO 27001, ENS: no. The founder does light self-testing with `selfcheck.sh`.
- Logging what people ask (content): no. The admin sees **spend per person only**, never message content. Less data stored means less liability.
- Read-only "company brain" connection for Claude/ChatGPT: skipped for now.
- Moving whole projects or memory between platforms: skipped for now.
- LiteLLM Enterprise license and the AGPL admin panel: skipped.

## Data rules (the "feel comfortable" part)
- Model makers (Moonshot/Kimi, DeepSeek, Zhipu...) never see customer data: we use their published models on **EU-owned hosts with no-log and no-training terms**.
- Before any customer data: leave OpenRouter and the DeepSeek public API. Switch `HOSTING_MODE=eu` and list the hosts in `MODEL_HOSTS` only when true.
- We do not want access to customer data. Preferred setup: each customer runs its own copy (their own EU server account, or ours with no human access). To decide.

## Interoperability (answers to the founder's questions)
- **Import tool does not burn tokens.** Importing a ChatGPT or Claude history is file parsing: LibreChat reads `conversations.json` directly, zero model tokens. Tokens are only used if someone continues an old chat later, and then only that chat is sent (cached after the first message). Memory import is the only step that needs a model, and it is a few cents.
  Caveat: ChatGPT Business/Enterprise workspaces have no self-service export; each user exports their own personal data or the admin requests it.
- **MCP**: wanted, but later. Design when it is time: a two-way "shared projects" MCP server (files + notes per project), login through the same Google/Microsoft account, content only leaves our boundary when the power user asks Claude or ChatGPT to read it.
- Shared Drive folder: kept only as the zero-build fallback.

## Why a minimum fee per company
A separate server per customer costs about EUR 6-10 per month. Pay-per-use plus 30% markup earns cents for a light user, so a 1-3 person company would not cover its own server. A flat platform fee (EUR 10-15 per company) or a minimum of about 5 seats solves it. If the customer owns the server account, the fee can disappear.
